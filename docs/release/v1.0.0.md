# SettleFlow v1.0.0 Release Notes (Draft)

**Not released. No tag or public GHCR image is authorized by this draft.** These notes define the intended first stable finance-grade simulation and must be regenerated/reviewed against the exact candidate before release.

## What v1 demonstrates

- Merchant-scoped, hashed API-key authentication and explicit scopes.
- ETB/USD Payment Intent create/read, deterministic direct full capture, and partial/full refunds using integer minor units.
- Stored idempotency ownership/fingerprints/response replay under retries and concurrency.
- PostgreSQL-enforced immutable, balanced double-entry capture/refund/Settlement postings.
- Transactional outbox publication, RabbitMQ confirms/manual acknowledgements, durable inbox deduplication, and poison-message DLQs.
- Merchant Webhook endpoint lifecycle, encrypted 24-hour secret rotation overlap, SSRF-safe exact-byte HMAC delivery, immutable attempts, and seven-attempt retry/dead-letter lifecycle.
- Merchant/currency-isolated Settlement batching with snapshotted `settlement_fee_v1`, post-settlement refund adjustments, guarded Ledger finalization, and no real payout.
- Bounded mock-provider CSV reconciliation with deterministic matching, mutually exclusive buckets, and non-mutating reports.
- Structured redacted telemetry, internal probes/metrics, executable alerts/runbooks, secure OCI release simulation, deterministic demo, CI/security/supply-chain evidence, and isolated PostgreSQL recovery.

## Public contracts

- HTTP API major: `/v1`; machine contract: [OpenAPI](../api/openapi.json).
- Domain events: `payment.created.v1`, `payment.captured.v1`, `payment.refunded.v1`, `settlement.finalized.v1`, and `reconciliation.completed.v1` with closed schemas in [event documentation](../events/README.md).
- Webhook delivery is at least once and signs exact retained event bytes. PostgreSQL remains authoritative; RabbitMQ/Webhooks/telemetry are not.
- Money is integer minor units, ETB or USD only, with no FX.

## Operational limitations

- This is not production-ready, certified, regulated, or supported for real funds, providers, payouts, card data, or personal data.
- Catastrophic RabbitMQ-volume loss may lose events already marked published but not durably consumed. Topology is declarative, but there is no controlled asynchronous replay tool or full broker RPO claim.
- The OCI/Compose topology is a release simulation with one PostgreSQL writer, not a production/multi-region platform.
- No 24x7 monitoring, SLA, backup maintainer, or managed deployment/support commitment exists.
- The isolated restore proves restorability and a 78-second RTO result against the 60-minute reference target. The 15-minute RPO is **not claimed** until a sustained backup cadence is exercised.
- The first public version has no prior-public-release upgrade proof. From `v1.0.1`, the previous public fixture and upgrade path are mandatory.
- Performance source scenarios exist, but final candidate measurements must be inserted below before release.
